# Cardsboard CLI - Implementation Plan

## Project Overview

Cardsboard CLI is a local development tool that brings AI-powered design exploration to React projects. Unlike the web app version, this runs locally in your project directory, giving it direct access to your components, design system, and build pipeline.

**Key Philosophy**: Like Storybook, but for AI-powered design exploration on an infinite canvas.

---

## End-to-End User Experience

### Phase 1: Installation (One-time)

```bash
cd my-project
npm install -D cardsboard-cli
```

**What happens:**
- Package installs to `node_modules/cardsboard-cli/`
- Post-install hook adds script to `package.json`

**User sees:**
```
✓ Cardsboard CLI installed
✓ Added "cardsboard" script to package.json
✓ Run: npm run cardsboard
```

---

### Phase 2: First Run (Setup)

```bash
npm run cardsboard
```

**What happens:**
1. CLI starts Express server (instant)
2. Opens browser to `http://localhost:3001`
3. Web UI shows loading state: "Scanning your project..."
4. Background scan discovers components
5. Canvas appears with component palette

**User sees in browser:**
```
🎨 Cardsboard v0.1.0

✓ Server ready on http://localhost:3001
✓ Scanning src/ directory...
✓ Found 23 components
✓ Detected: Next.js 14 + Tailwind CSS
✓ Canvas ready
```

### Phase 3: Daily Workflow Scenarios

#### Scenario A: Explore Existing Components

**User drags "Button" from sidebar onto canvas**

**What appears:**
- A card/node showing the actual Button component
- Renders with real props
- Interactive: Can click it, see hover states

**User can:**
- Double-click to edit props in side panel
- Resize the card
- Duplicate it (Cmd+D)
- Delete it (Delete key)

---

#### Scenario B: Generate New Design

**User types in chat:** "Create a mobile grocery list app"

**What happens:**
1. AI analyzes their design system (tailwind.config.ts, globals.css)
2. AI knows their Button, Input, Card components
3. AI generates React code using THEIR imports:

```tsx
import { Button } from "@/components/ui/button"
import { Input } from "@/components/ui/input"
import { Card } from "@/components/ui/card"

export default function GroceryList() {
  const [items, setItems] = useState([])
  // ... their design system applied
}
```

4. New node appears on canvas with live preview

**User sees:**
- Phone-sized card showing grocery list app
- Fully interactive: Can add items, check them off
- Uses their actual color scheme and components

---

#### Scenario C: Create Variations

**User selects grocery list and types:** "Create 3 variations with different design languages"

**What happens:**
- AI generates 3 variations side-by-side:
  - **Variation 1**: Minimal, clean (current style)
  - **Variation 2**: Bold, colorful (different use of accent colors)
  - **Variation 3**: Dark mode (inverted color scheme)

**User sees:**
- 3 complete, working grocery list apps
- All use their components but styled differently
- Can compare and choose favorite

---

#### Scenario D: Live Iteration

**User edits Button component in their IDE**

**What happens:**
- File watcher detects change
- WebSocket broadcasts update
- All Button instances on canvas update instantly
- All 3 grocery list variations show new button style

**User sees:**
- Live reload without refresh
- Changes apply to everything using Button

---

### Key Components

#### 1. CLI (`src/cli/index.ts`)
- Parse CLI args (`--port`, `--config`)
- Start dev server
- Open browser automatically
- Handle graceful shutdown

#### 2. Component Scanner (`src/scanner/`)
**Intelligent Discovery:**
- Scan `src/` recursively for `*.tsx` files
- Parse TypeScript AST to find exported components
- Extract prop interfaces
- Resolve import paths (handle `@/` aliases)
- Cache results to `.cardsboard/cache.json`

#### 3. Server (`src/server/`)
**Express + WebSocket:**
- Serve canvas UI on `/`
- API routes:
  - `GET /api/components` - List discovered components
  - `POST /api/generate` - AI generation endpoint
  - `GET /api/component/:name` - Get component code
- WebSocket for live file updates

#### 4. Canvas UI (`src/canvas/`)
**React Flow Canvas:**
- Infinite canvas with zoom/pan
- Node types: Design, Text, Sketch, Image, Section
- Component palette sidebar
- AI chat interface (BottomBar)
- Props editor panel

#### 5. AI Integration (`src/ai/`)
**Context-Rich Generation:**
- Read tailwind.config.ts for design tokens
- Read globals.css for custom styles
- Know component APIs from prop parsing
- Generate using actual component imports

## Technical Implementation

### File Watching

```typescript
import chokidar from 'chokidar';
import { WebSocketServer } from 'ws';

const watcher = chokidar.watch('./src/**/*.{tsx,jsx,css}', {
  ignored: /node_modules/,
  persistent: true
});

watcher.on('change', (path) => {
  // Re-scan changed file
  const component = reparseFile(path);
  // Broadcast to all connected clients
  wss.clients.forEach(client => {
    client.send(JSON.stringify({
      type: 'component:updated',
      data: component
    }));
  });
});
```

### Component Discovery

```typescript
// Find all exported React components
const components = scanDirectory('./src', {
  extensions: ['.tsx', '.jsx'],
  exclude: ['node_modules', '.next', 'dist']
});

// Parse each file
for (const file of components) {
  const ast = parseTypeScript(file);
  const exports = findExportedComponents(ast);
  const props = extractPropTypes(exports);
  
  registry.add({
    name: export.name,
    filePath: file,
    props,
    source: readFile(file)
  });
}
```

### AI Prompt

```typescript
const prompt = `
You are generating React components for a ${framework} project.

DESIGN SYSTEM:
${readTailwindConfig()}
${readGlobalsCSS()}

AVAILABLE COMPONENTS:
${registry.getAll().map(c => `- ${c.name}: ${c.props}`).join('\n')}

Generate a ${componentType} component that:
1. Uses the available components above
2. Follows the design system
3. Is fully functional with state/hooks
4. Uses TypeScript with proper types

USER REQUEST: ${userQuery}
`;
```

## Key Decisions

1. **Framework Support**: Start with Next.js, expand to Vite/CRA later
2. **Port**: Auto-increment if 3001 is taken
3. **State Management**: Start with React Context, migrate to Zustand later
4. **DesignNode**: Keep iframe HTML initially, add React component mode later
5. **Dependencies**: Don't install - use project's existing node_modules
